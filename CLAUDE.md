# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is **Polar- "dock"** — the backend API + agent core of a multi-module platform. The Go module is named `gin-auth-app` (historical) but everything lives under `internal/app/dock`. The dock is identity + LLM proxy + collaboration core; every vertical feature (iosdist, video, wg, hosts, etc.) is being extracted into its own standalone service that talks back via the `/internal/v1/*` HMAC API. See `README.md` for the product overview and `doc/arch/open-platform.md` for the platform direction.

The web UI is **not** in this repo — it lives in the private `networkextension/polar-dock-ui` repo. The `modules/` directory holds checkouts of the companion repos (polar-sdk, polar-hosts, etc.), each its own separate Go module — they are **not** part of the dock build and have no `go.work` linkage.

## Commands

`go` is invoked with an explicit GOCACHE in this project (the in-repo `.gocache/` is gitignored; use `/tmp`):

```bash
# Run the backend (defaults to :8080)
env GOCACHE=/tmp/polar-go-cache go run ./cmd/dock

# Build with git/build metadata baked in (surfaced on /api/system/info)
scripts/build-dock.sh                              # native, CGO_ENABLED=0 static
GOOS=linux GOARCH=amd64 scripts/build-dock.sh      # cross-compile

# Test — the dock root module only (modules/ are separate, excluded by ./...)
env GOCACHE=/tmp/polar-go-cache go test ./...
env GOCACHE=/tmp/polar-go-cache go test ./internal/app/dock -run TestName   # single test
env GOCACHE=/tmp/polar-go-cache go vet ./...

# Regenerate the API catalog after adding/changing routes (see below)
env GOCACHE=/tmp/polar-go-cache go generate ./internal/app/dock
```

Tests are self-contained — they do not require a live Postgres/Redis. Local dev DB bootstrap and full env-var setup live in `doc/deploy-local.md`.

## Architecture

### Single package, file-per-domain

Nearly all backend code is in **one Go package** `internal/app/dock` (~150 files), split by domain prefix rather than subpackages: `auth_*`, `teams_*`, `chat_*`, `chat_rooms_*`, `ai_agent*`, `attachments_*`, `iosdist_*`, `llm_proxy_*`, `host_*` / `hosts_*`, `agents_*`, `internal_api_*`, `markdown_*`, `post_*`. Within a domain you'll typically find `<domain>_handlers.go` (HTTP) + `<domain>_store.go` (data access). The `Server` struct in `app.go` holds all shared state (db, redis, hubs, config); routes are wired in `app.go:registerRoutes()`.

### Schema lives in code, not migration files

The Postgres schema is **embedded in `internal/app/dock/store.go` (`openDB()`)** as `CREATE TABLE IF NOT EXISTS` + idempotent `ALTER TABLE` statements applied at boot — there is no migration-runner framework. To add a column or table, edit `openDB()`. The top-level `migrations/` dir is old one-off SQL; `scripts/migrate/` is the active per-plugin **extraction** tooling (`<plugin>-schema.sql` / `<plugin>-data.sh`) that carves owned tables into each plugin's own database per `doc/arch/database-ownership.md` — neither is a dock-core migration step.

### Workspace model is pervasive

A workspace == a team. **Every domain table carries `workspace_id`**, and routes resolve it from the `X-Workspace-Id` header (falling back to the caller's auto-created personal team). When adding any resource, key it by `workspace_id`. The platform "system" workspace owns genuinely platform-wide rows (shared LLM configs, etc.). See `teams.md` and `doc/arch/database-ownership.md`.

### Sessions, not JWTs

Auth is Redis-backed sessions (30-min access cookie + 30-day rotating refresh), not JWTs — chosen for atomic revocation. Middleware: `AuthMiddleware()` (required), `GuestMiddleware()`. See `doc/auth.md` and `doc/auth-refresh.md`.

### Three route surfaces (`app.go:registerRoutes`)

- `/api/*` — the user-facing API, session-cookie auth.
- `/internal/v1/*` — plugin→dock service calls, gated by `hmacPluginAuth()` (HMAC-SHA256 signed headers). Production must **also** block `/internal/` at nginx — the HMAC is the second wall. Contract: `doc/arch/internal-api-v1.md`.
- `/ws/*` — WebSocket bridges: `/ws/chat`, `/ws/agent` (polar-agent transport), `/ws/host/:id/shell|vnc/:run_id`. Auth is done inline (gin middleware can't run cleanly across a WS upgrade).
- `/metrics` — Prometheus, gated by `METRICS_TOKEN` (404 if unset).

### Agent runtime: the chat IS the runtime

When a bot has a `polar-agent` CLI paired to it, the dock just routes bytes: chat message → WS → local agent → tool exec or kimi-cli passthrough → stdout → back to chat. The platform LLM (Kimi, seeded from `KIMI_API_KEY`) drives the `read_file`/`write_file`/`run_cmd` tool loop, or is bypassed entirely in `--kimi` passthrough mode. See `ai_agent*.go` and `agent_hub.go`.

### API catalog is generated by static analysis

`cmd/api-catalog-gen` parses `internal/app/dock` with go/ast to recover each route's body/query/params/auth, writing `internal/app/dock/api_catalog.gen.json` (go:embed → served at `/api/_catalog`) and `doc/api/catalog.json`. After changing routes, run `go generate ./internal/app/dock`. The live `GET /api/_routes` (from `meta_handlers.go`) is authoritative for method+path.

### Graceful degradation by design

Missing optional infra degrades rather than crashes: no GeoLite2 → login works without geolocation; no R2 creds → uploads use local filesystem; no SMTP → email verification disabled but auth core lives. Optional secrets (`IOSDIST_RESOURCE_KEY`, `POLAR_CREDENTIAL_KEY`) are AES-256-GCM at-rest keys — when unset, data is stored cleartext with a warning flag rather than failing.
