小额不良资产的 AI 催收，难点从来不在"能不能自动化打电话"，而在**合规边界**和**案件分层经济性**。在动手设计前，我想先把今年生效的催收监管基线核实清楚——这块如果搞错，整个系统的执行层就是违规的——然后再给你一套能落地的架构。核实清楚了。我再确认一下新国标对 **AI/智能催收** 这一块的具体约束——这部分直接决定你执行层 agent 能做什么、不能做什么。核实完毕，下面这套设计就建立在已验证的监管基线上。

先把**红线**钉死，因为它直接决定执行层 agent 的行为边界——这不是合规附录，是架构约束本身。现行依据是国标《互联网金融 个人网络消费信贷 贷后催收风控指引》（国标公告 2025 年第 4 号，主管部门央行，归口 TC180，已替代 2024 年中互金协会的行业指引）。对你的系统有刚性约束的几条：

- 催收作业不应在每日 22:00 至次日 8:00 进行，每日电话催收不能超过 3 次（含外访等任何形式）。
- 金融机构和第三方催收机构应只向债务人催收，不应向联系人催收——紧急联系人不得随意触碰。
- 催收记录定期自查每年至少一次；金融机构对第三方机构定期检查和突击检查每年至少各一次，检查记录保存期限应至少 2 年。
- 最关键的一条：新国标增强了对人工智能技术应用的管理要求，调整了风险告知义务和业务信息共享义务，并强调催收风险责任的落实，主体责任压在金融机构身上。

换句话说，AI 外呼/智能催收已经被单独点名监管，"AI 不能成为责任黑洞"是写进国标精神里的。这决定了整个系统的骨架。

## 三条设计原则

**一、分层经济性是目的，不是功能。** 小额（几百到几万、海量长尾）做 AI 的唯一理由是单位经济——一个 ¥3,000 的户养不起人工坐席反复跟进。系统目标函数是 `max(回收金额 × 回收率) / (触达成本 + 合规风险敞口)`。AI 的杠杆全在长尾自动化，人工和诉讼只留给 ROI 跨过门槛的户。

**二、护栏即架构（LLM proposes, policy engine disposes）。** 这是最重要的一点：时间窗、频次上限、催收对象校验、话术红线**绝不能交给 LLM "记住"**。必须是一个确定性的 policy engine 横在 agent 意图和任何对外动作之间——agent 产出意图，策略引擎做准入裁决并落审计日志。LLM 概率性地违规一次，对你客户就是一次监管事故。

**三、数据不出域。** 不良资产包是 PII 密度极高的数据（身份证、手机号、银行卡、联系人、流水，可能涉征信），叠加 PIPL 和国标的"信息共享义务"约束，这是你"compute comes to the data"论点的教科书级场景。模型和 agent 在委托方/资产持有方的环境里就地编排，而不是把数据吐给 SaaS 催收平台。这本身就是 daotian 控制平面对这个行业的差异化卖点。

## 案件分层与策略路由

入库即打分，五个维度：还款能力（收入代理、多头负债）、还款意愿（历史还款行为、触达响应、态度）、可触达性、账龄/逾期阶段（M1/M2/M3+/呆账）、诉讼价值（小额单户起诉常常算不过账）。打分结果路由到几条 track：

- **自助还款 track**：意愿高、只差临门一脚 → 极简还款入口 + 轻提醒
- **协商和解 track**：能力受限 → 减免/分期方案
- **法催 track**：有能力无意愿或策略性逾期 → 律师函 → 支付令 → 诉讼
- **失联修复 track**：合规雷区，修复手段极易越界获取 PII，必须严格走合法渠道
- **暂缓/核销 track**：无能力无价值，停催候选

## Agent 编排架构

multi-agent 分工，编排层管单案的状态机（每个户是一个长生命周期 workflow）：

1. **画像/评分 Agent** — 打分、分层、推荐策略
2. **策略编排 Agent（orchestrator）** — 跨渠道排布触点序列、维护单案 campaign 状态
3. **外呼对话 Agent** — ASR+LLM+TTS，在授权范围内合规对话与协商
4. **文本触达 Agent** — 短信/IM/信函生成
5. **协商方案 Agent** — 在政策边界内生成减免/分期、起草和解协议
6. **法务 Agent** — 诉讼价值评估、律师函/支付令/起诉状生成、进程跟踪、批量诉讼支持
7. **质检/合规 Agent** — 对录音/转写做事后质检、投诉识别、违规线索标记（对接国标的自查义务）

注意：**护栏 policy engine 不是 agent**，是确定性基础设施。每个对外动作过它一道——校验时间窗、累计频次、催收对象是否为债务人本人、话术是否触红线（威胁、软暴力、冒充公检法、虚假法律后果陈述）。高风险动作（立案、超权限减免、升级法催）强制 human-in-the-loop，因为主体责任在金融机构、不能让 AI 兜底。

外呼 agent 还有个开场必答题：**是否、如何告知"这是 AI/通话录音"**。国标既然强化了风险告知义务又单点 AI，保守做法是默认自报或至少告知录音并留痕。这条你需要和客户法务一起拍板。

## 法催与诉讼时效子系统

行业有"法催时代"的讨论。小额单户起诉不经济，所以打法是**支付令**（成本低、对无争议小额债务快）、**互联网法院批量诉讼**（标准化、AI 批量生成文书）、有仲裁条款的走仲裁。AI 的活是 triage 哪些户跨过诉讼价值线、批量生成文书、跟踪进程。

一个容易被忽略的技术-法律点：**合规催收记录本身构成"主张债权"，可中断诉讼时效**。所以即便是软性催收，只要留痕规范，就有保全债权的法律功能。系统应当把"时效管理"作为一等公民显式跟踪，而不是只盯回款。

## 需要你先拍板的几个点

委托关系（你客户是买了资产包的持有方？委托/受托的主体责任如何分配，直接影响责任设计）；**合规外呼线路**的获取——这是运营瓶颈也是高频违规源，技术再合规、线路不合规一样出事；以及失联修复的边界把控。
