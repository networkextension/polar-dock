## 📋 全站问题汇总与修改意见

---

### 🔴 严重问题

**1. Dashboard 页面内容永久空白（dashboard.html）**
- **现象**：右侧主内容区始终显示 `Loading...`，加载超时后依然空白，没有任何 widget 或内容渲染。
- **影响**：Dashboard 作为核心首页完全失去功能，用户进来后无任何信息可读。
- **建议**：检查数据请求是否超时或接口报错；增加加载失败后的错误提示状态（如"数据加载失败，请刷新重试"）；不应让用户长时间面对一个空屏。

---

### 🟠 中等问题

**2. Chat 页面 `<title>` 标签错误（chat.html）**
- **现象**：浏览器标签页标题显示为"**发送**"，而不是"私聊"或"Chat"。
- **影响**：用户在多标签场景下无法通过标题辨认页面；SEO/可访问性评分下降。
- **建议**：将页面 `<title>` 改为"私聊"或"Chat — 庐山"，与其他页面的命名风格保持一致。

**3. Editor（Markdown 编辑器）顶部工具栏文字溢出截断（editor.html）**
- **现象**：顶部右侧工具区有按钮文字被截断为竖排"建一条记录"，显示破损。
- **影响**：用户无法识别该按钮的完整功能，点击意愿和操作准确率降低。
- **建议**：检查该按钮的容器宽度和 `white-space` 属性；可改为 icon+tooltip 形式，或增加容器宽度使文字完整显示。

**4. LLM 页面数据持续加载（llm.html）**
- **现象**："LLM 市场"和"我的 API Token 用量"两个区块都显示`加载中...`，无法展示实际数据。
- **建议**：同 Dashboard 问题，需增加超时后的错误状态提示，避免用户看到永久加载动画。

**5. LLM 计费页（llm-billing.html）数据区为空**
- **现象**：两个区块（管理员·单价 / 管理员·团队配额）均无数据，空旷，只有说明文字。
- **建议**：若确实无数据，应展示空状态提示（如"暂无配置，请先创建"）；若是加载失败，同样需要错误反馈。

**6. LLM 申请审核页（llm-apps.html）数据区完全空白**
- **现象**：仅显示一段说明文字，申请记录区域为空，没有空状态设计。
- **建议**：添加空状态说明（如"暂无申请记录"）或加载中状态提示。

---

### 🟡 一般/体验问题

**7. 工作区（teams.html）左侧列表中"工作区"标签语义重复**
- **现象**：左侧顶部有一个"工作区"标签（分组标题），列表中的每个条目下方也都标注"团队工作区"，信息冗余。
- **建议**：精简文案，列表项中的"团队工作区"标签可改为更具区分意义的信息（如团队人数、状态），或直接省略。

**8. 工作区头像占位图（teams.html）**
- **现象**：所有工作区均显示默认的房子图标（⌂），没有头像。
- **建议**：对于没有自定义头像的工作区，可用名称首字母作为彩色头像占位（如"我"→橙色圆形），提升视觉区分度；当前所有条目外观完全一致，难以区分。

**9. 创作页面（creation.html）内容区与编辑器功能定位重叠**
- **现象**："创作"和"Editor"两个导航项均为文章编辑器，但 UI 有差异（创作页只有一个大标题输入框，Editor 有 Markdown 编辑器）。
- **建议**：在导航栏或页面内增加说明，明确两者的区别（如：创作 = 帖子编辑器 / Editor = Markdown 文档编辑器），避免用户困惑。

**10. Chat 新建对话区域 UI 缺乏视觉引导**
- **现象**：`新建对话`区域有 Bot 选择下拉框（"iPhone · research · Bot"、"自动选择"两行），但无任何标签说明这些下拉框的作用。
- **建议**：为每个下拉框添加 label（如"选择 Bot"、"选择设备"），提升可用性。

**11. Skills 页面目标 HOST 下拉框显示"（工作区暂无 host）"**
- **现象**：技能安装目标 HOST 选择器无可选项。
- **建议**：显示空状态时，应同时提示用户如何添加 host（引导链接），而非仅显示括号内的提示。

**12. 危险区（teams.html → 危险区 tab）"删除工作区"按钮过于突出**
- **现象**："删除工作区"按钮为鲜红色 + 大字体，视觉权重极高，容易误点。
- **建议**：增加二次确认弹窗（输入工作区名称确认删除）；可考虑将按钮默认为灰色，hover 后变红，减少误操作风险。

**13. Bot 管理页（bots.html）有明显的弃用警告但无迁移引导**
- **现象**：黄色警告条提示"Classic bot 创建表单将下架"，但缺少一键引导到新流程的明确入口（"→ 去新建 agent token"链接虽有，但样式不显眼）。
- **建议**：将迁移链接设计为更突出的按钮，或在警告条中直接嵌入操作按钮。

---

### 🔵 语言/一致性问题

**14. 中英文导航标签混用不统一**
- **现象**：侧边导航混用中英文，如 Posts、Markdowns、Dashboard、Editor、Chat、LLM、Bot 管理、Skills、Video Studio、iOS 分发 等，中英文随意混排。
- **建议**：统一选择一种风格（全中文或行业惯用英文），目前混用状态在专业感和一致性上较弱。可参考：Posts → 帖子，Markdowns → 文档，Editor → 编辑器，Chat → 私聊（左边已有"私聊"标题，但导航里写 Chat）。

**15. 顶部右侧按钮语言不统一**
- **现象**：同一个 Editor 页面顶部同时出现"AI 润色"（中文）和"Preview"（英文），Markdowns 页面有"浏览所有公开发布的文档"和"返回控制台"（中文）等不一致现象。
- **建议**：统一 UI 文案语言策略，对同一页面内的操作按钮使用相同语言。

---

### 总结

| 优先级 | 问题 | 建议行动 |
|---|---|---|
| 🔴 立即修复 | Dashboard 永久空白 | 修复数据加载逻辑 / 加错误状态 |
| 🟠 尽快修复 | Chat 标题错误、Editor 文字截断、LLM 加载中 | 修复 `<title>`、修复布局溢出 |
| 🟡 迭代优化 | 空状态缺失、危险按钮防误操作、导航引导不足 | 增加空状态 UI、二次确认弹窗 |
| 🔵 长期规划 | 中英文混用、创作/Editor 功能区分 | 统一设计语言和命名规范 |
