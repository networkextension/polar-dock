# MiroFish 分布式通用租用算力平台 —— 系统架构设计文档 (Architecture Specification)

## 1. 系统架构全景 (System Architecture Overview)

MiroFish 是一个将**全球去中心化闲置算力**直接转化为**自主 AI 生产力**的下一代分布式算力网络。它不仅租售裸算力（GPU/CPU），更通过内置的数字外骨骼（系统级调试工具链），为 AI Agent 提供了一个无视公网恶劣环境、具备自我演进能力的云原生超操作系统环境。

## 2. 核心分层架构 (Layered Architecture)

### 2.1 基础设施与算力供给层 (Infrastructure & Supply Layer)

* **节点接入端 (MiroFish Daemon)**：
* **Windows 供给侧**：集成 **Wintun 驱动** + 用户态 WireGuard 协议栈 + kcptun 客户端。兼容消费级游戏显卡（RTX 3090/4090）与专业工作站（RTX 6000 实例），一键挂机接入。
* **Apple/Linux 供给侧**：基于 FreeBSD 移植版 WireGuard 核心，无缝支持 macOS、iOS 和 Android 模拟器/实体设备节点。


* **计算沙箱 (Compute Sandbox)**：
* 通过定制化 Hypervisor（如 macOS 的 `Virtualization.framework` 或 Linux Firecracker）建立秒级快照恢复（Snapshot & Restore）的隔离沙箱。
* Agent 的所有编译、执行、破坏性调试（如 Kernel Tweak）均在沙箱内进行，搞砸一键 Rollback，确保宿主机绝对安全。



### 2.2 网络协议栈与传输层 (Network Stack & Transport Layer) —— *双轨拓扑*

为了对抗跨国、跨运营商的恶劣公网环境，网络层采用**双轨并行（Dual-Track）机制**：

* **轨道 A：控制与流媒体面 (Surge App + kcptun)**
* **职责**：负责高频、低延迟、强交互的流数据传输（如 VNC 远程画面、Shell 伪终端 TTY 流、LLDB 交互指令）。
* **逻辑**：在激进的 KCP 协议基础上嵌入 Surge 的代理转发机制，通过 10%~20% 的带宽冗余重传，强行**对抗公网 10%~30% 的极端丢包**，确保 Agent 视觉（VNC 帧）和听觉（日志流）永不卡顿。


* **轨道 B：数据与代码面 (Custom WireGuard Mesh)**
* **职责**：负责大带宽、高隐私的数据传输（如大模型权重分发、TB 级数据集同步、Git 源码推拉）。
* **逻辑**：通过中心化控制器（如仿 Tailscale 架构）动态下发密钥，在分布式节点间构建端到端加密的 P2P 虚拟局域网（Overlay Network）。配合中继节点（DERP），实现 100% 成功率的 NAT 内网穿透。



### 2.3 智能 Agent 与技能工具层 (Agent & Skill Layer)

平台不再向最终用户交付冰冷的终端，而是交付**自带调试工具箱的 Agent 开发者群组**：

* **工作站核心**：以 Coder Claude / Codex 等多模态 LLM 为脑。
* **高级底层调试 Skill 库**：
* **LLDB Skill**：平台将裸 LLDB TTY 封装为结构化 API（如 `get_backtrace()`、`read_memory()`），防止 Agent 陷入命令语法死循环。用于 Native（C/C++/Swift）应用崩溃拦截。
* **KDP / JTAG Skill**：提供内核级（XNU）与底层硬件仿真级接口，用于复杂的系统移植与内核调优任务。
* **IDA Pro / Ghidra Skill**：开发特定插件，将反编译伪代码进行控制流图（CFG）摘要化，按需喂给 Agent，避免撑爆大模型上下文（Context Window）。



### 2.4 业务闭环与自我演进层 (Execution & Self-Evolving Layer)

通过 **Actor-Critic（执行-评审）** 机制，在无人类干预的情况下实现代码的持续迭代：

1. **分发（Dispatch）**：Agent 接收到来自平台的生产活计。
2. **执行与调测（Execute & Debug）**：Agent 在沙箱内编写代码，通过 kcptun 弱网隧道实时观察 VNC/Shell 反馈。若编译失败或触发 Crash，自动调用 **LLDB/IDA Skill** 进行根因分析，将报错信息作为 Input 重新迭代。
3. **拦截与质检（Review & Audit）**：代码通过静态分析（Lint）和自动化测试（CI）后，提交至评审 Agent。
4. **落库（Commit）**：通过代码质量审核后，自动通过 WireGuard 暗网安全提交至目标的远端 Git Repo。

## 3. 核心业务流程 (Key Workflow Sequence)

### 3.1 节点上线与网络组网流程

1. 供给侧节点启动 `MiroFish Daemon`，上报硬件资产（GPU/CPU/内存）。
2. 调度中心通过并下发路由令牌，节点加载 **Wintun / FreeBSD WG 内核**。
3. 节点同时启动 **kcptun 隧道** 挂载至平台最近的 Surge 边缘节点。
4. 控制平面根据 **ACL 策略**，将该节点划分至专属虚拟网络段，等待接活。

## 4. 关键技术指标与优化策略 (KPIs & Optimization)

1. **弱网对抗指标**：在 **丢包率 $\le$ 30%，延迟 $\le$ 300ms** 的跨国公网环境下，通过 kcptun 流控算法调优，确保 VNC 帧率维持在 15fps 以上，TTY 键入延迟 $\le$ 50ms。
2. **安全合规指标 (PoE - Proof of Execution)**：摒弃传统的无效算力证明，采用**基于 Agent 行为的确定性验证**。通过校验 Git 提交的编译哈希、LLDB 的真实内存地址以及静态审计结果，隐式判定算力节点是否存在欺诈。
3. **计算溢价率**：由于平台向外打包输出了“算力+网络加速+自愈 Agent”的全栈生产力，其算力租售溢价率预计比传统裸 GPU 租赁平台（如网络受限的普通机房）提高 200% ~ 300%。

## 5. 项目三阶段演进路线 (Roadmap)

* **Phase 1: 最小可行性验证 (MVP)**
* 完善现有的 iOS/macOS/Android 端的 WireGuard 栈及 Surge+kcptun 调优。
* 通过 Wintun 攻克 Windows 端。
* 手工观察并固化第一批 LLDB/IDA 自动化 API 技能。


* **Phase 2: 算力平台化与去中心化调度 (Scale)**
* 推出轻量化封装的 Daemon 客户端，向技术社区开放算力供给节点。
* 上线基于 P2P Mesh 的中心化协同服务器（Coordination Server），打通全球动态 ACL 与中继（DERP）系统。


* **Phase 3: 经济学清算与全通用化 (Ecosystem)**
* 引入微支付清算体系（基于 L2 网络或代币经济学），实现算力供给方自动躺赚，消费方按 Agent 任务复杂度/消耗算力弹性买单。
